4. Detailed Defect Specifications (IEEE 829 Template)

DEFECT ID: BUG_FFC_001 | Password Maximum Length Hard-Capped at 12 Characters SEVERITY: MAJOR | PRIORITY: P2
Module Authentication / Registration Sub-Module / URL /auth/login, /auth/reset-password
Defect Type Security / Validation Constraint Flaw Reproducibility 100% (Always Reproducible)
Pre-conditions User is on the Login or Reset Password page.
Test Data Used Password: NimapTechSecure@2026! (21 characters)
Steps to Reproduce
  1. Navigate to https://test.fieldforceconnect.com/auth/login.
  2. In the Password input box, enter a secure password exceeding 12 characters (e.g., NimapTechSecure@2026!).
  3. Observe the inline helper text validation error under the field.
Expected Result Per NIST SP 800-63B standards, password inputs should allow passphrases up to at least 64 characters to support modern password managers and strong entropy.
Actual Result Inline error message displays: "Password cannot exceed 12 characters". Submission is blocked for passwords with > 12 characters.
Technical Remediation
In React Hook Form rules (Login-bCrUzcYN.js), update maxLength: { value: 64, message: "Password cannot exceed 64 characters" } and adjust the backend hashing schema.
DEFECT ID: BUG_FFC_002 | Absence of Password Visibility (Eye) Toggle SEVERITY: MODERATE | PRIORITY: P3
Module Authentication Sub-Module / URL /auth/login
Defect Type UI / Usability Flaw Reproducibility 100% (Design Omission)
Pre-conditions User is on the login page.
Test Data Used Password: P@ssw0rd#2026
Steps to Reproduce
  1. Navigate to https://test.fieldforceconnect.com/auth/login.
  2. Type characters into the Password input box.
  3. Look for an eye icon at the right edge of the field to preview or unmask the text.
Expected Result A clickable eye icon toggle should allow toggling input visibility between type="password" and type="text" to prevent typos.
Actual Result No visibility toggle icon is present. Password is permanently masked with bullet points.
Technical Remediation
Add Material-UI InputAdornment with an IconButton containing Visibility and VisibilityOff icons.
DEFECT ID: BUG_FFC_003 | 4-Digit OTP Input Rejects Clipboard Paste SEVERITY: MODERATE | PRIORITY: P2
Module Authentication Sub-Module / URL /auth/otp-verification
Defect Type Functional / Usability Reproducibility 100%
Pre-conditions User requested OTP login and has 4-digit code in clipboard.
Test Data Used Clipboard Text: "7392"
Steps to Reproduce
  1. Navigate to /auth/otp-verification.
  2. Focus the first OTP input digit slot.
  3. Press Ctrl + V (or Right-Click > Paste).
Expected Result The 4-character string should distribute across Box 1 ('7'), Box 2 ('3'), Box 3 ('9'), Box 4 ('2').
Actual Result Only the first character ('7') is pasted into Box 1; characters 2, 3, and 4 are dropped. User must manually type each box.
Technical Remediation
Attach an onPaste event listener on the OTP input group to capture e.clipboardData.getData('text') and set all 4 indices.
DEFECT ID: BUG_FFC_004 | Sign Up Submit Button Silently Disabled SEVERITY: MAJOR | PRIORITY: P2
Module Sign Up / Registration Sub-Module / URL /auth/register
Defect Type UX / User Onboarding Flaw Reproducibility 100%
Pre-conditions User is on the user registration page.
Test Data Used Valid Company, Person, Mobile, Email; Unfilled Dropdowns
Steps to Reproduce
  1. Navigate to https://test.fieldforceconnect.com/auth/register.
  2. Fill Company Name, Contact Person Name, Mobile Number, and Email ID.
  3. Leave Timezone or Currency untouched if cleared.
  4. Attempt clicking 'Submit'.
Expected Result Submit button should remain enabled and trigger visible red error borders/messages highlighting missing fields upon click.
Actual Result Button is rendered as disabled={!isValid} without any tooltip or feedback explaining which field is invalid.
Technical Remediation
Remove disabled={!p} from the submit button; invoke React Hook Form's trigger() on submit to reveal errors.
DEFECT ID: BUG_FFC_005 | Case-Sensitive Email Lookup on Forgot Password SEVERITY: MAJOR | PRIORITY: P1
Module Account Recovery Sub-Module / URL /auth/forget-password
Defect Type Functional / Account Recovery Failure Reproducibility 100%
Pre-conditions Account exists registered with email tester@fieldforce.com.
Test Data Used Input: Tester@FieldForce.com (Capitalized)
Steps to Reproduce
  1. Navigate to /auth/forget-password.
  2. Enter valid registered email with capitalized letters (e.g., Tester@FieldForce.com).
  3. Click 'Submit' button.
Expected Result RFC 5321 mandates case-insensitive email domain handling. The application must normalize email to lowercase and dispatch the reset OTP.
Actual Result Backend API performs case-sensitive match; returns error and toast displays: "Failed to send OTP".
Technical Remediation
Apply emailOrMob.trim().toLowerCase() in the submit handler prior to API dispatch.
DEFECT ID: BUG_FFC_006 | Toast Notification Dismissal Too Rapid (< 2s) SEVERITY: MINOR | PRIORITY: P3
Module Attendance / Punch In Sub-Module / URL /dashboard, /attendance
Defect Type UI / Usability Reproducibility 100%
Pre-conditions User is authenticated and on Dashboard.
Test Data Used Standard Punch In Action
Steps to Reproduce
  1. Navigate to Dashboard.
  2. Click 'Punch In' button and confirm.
  3. Observe duration of the success toast notification.
Expected Result Toast notification should remain visible for 4-5 seconds and provide a dismiss button.
Actual Result Toast notification auto-dismisses in under 1.8 seconds, causing users to miss confirmation.
Technical Remediation
Configure React Hot Toast duration: toast.success("Punch In Successful", { duration: 4000 });.
DEFECT ID: BUG_FFC_007 | Mobile Number Field Accepts Non-Numeric on Paste SEVERITY: MAJOR | PRIORITY: P2
Module Customer Management Sub-Module / URL /customers (Add Customer Drawer)
Defect Type Input Validation / Data Integrity Reproducibility 100%
Pre-conditions User is logged in and opens the Add Customer form.
Test Data Used Pasted String: "98765-ABC-12"
Steps to Reproduce
  1. Navigate to /customers and click 'Actions' > 'New Customer'.
  2. Copy string "98765-ABC-12" to clipboard.
  3. Paste into Mobile Number field and click Submit.
Expected Result Field paste event should sanitize non-digit characters or display: "Mobile Number must contain digits only".
Actual Result Field accepts non-numeric characters on paste; submitting form triggers unhandled API 500 error.
Technical Remediation
Add input sanitizer on change/paste: e.target.value = e.target.value.replace(/\D/g, '').
DEFECT ID: BUG_FFC_008 | Unhandled Session Expiry Leads to White Screen SEVERITY: MAJOR | PRIORITY: P1
Module Session & Routing Sub-Module / URL Global Application Navigation
Defect Type Unhandled Exception / Routing Crash Reproducibility 100%
Pre-conditions User is on Dashboard; auth session cookie expires or is cleared.
Test Data Used Expired/Null Auth Session Cookie
Steps to Reproduce
  1. Log into Dashboard.
  2. Clear currentUser cookie in DevTools to simulate session expiration.
  3. Click any navigation menu link (e.g., 'Customers').
Expected Result Application catches 401 Unauthorized and smoothly redirects to /auth/login?returnUrl=/customers.
Actual Result Application crashes to a blank white screen with console error: "TypeError: Cannot read properties of null (reading 'roles')".
Technical Remediation
Implement React Error Boundary around root routes and add an Axios 401 response interceptor to redirect cleanly.
